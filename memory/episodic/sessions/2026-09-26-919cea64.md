## Goal
Ioseb wanted a foundational project structure and workflow for using Claude Code on this project: specs, ADRs, memory layers, session summarization, self-improvement proposals, context handoff, and recommended plugins, based on research into other Claude Code projects and the AI-native SDLC playbook. Within the same session, that workflow was then used to finish Phase 3 (call booking) and Phase 2 (leads and Telegram alerts) of the actual ProfitLens chatbot and troubleshoot it live.

## What was done
- Researched 40 repos from the AI Pulse Georgia "Claude Code Plugins and Skills" list at the code level, plus the AI-native SDLC playbook, then installed four official Anthropic plugins at project scope.
- Split the 159-line CLAUDE.md into `docs/intent.md`, `docs/spec.md`, `docs/plan.md`, 13 initial ADRs (later 19), `docs/workflow.md`, and a 57-line CLAUDE.md.
- Set up seven memory layers under `memory/` (working, episodic, semantic, procedural, decisions, proposals, personal), a SQLite search index, five project skills, rules, a statusline, and automatic session summarization tested end-to-end on this session's own transcript.
- Built and tested context handoff: 60% nudge, auto-compaction at 70%, red STOP indicator after 3 compactions.
- Built Phase 3 (calendar-based call booking in chat, clickable/typed time selection, Google Meet invites) and Phase 2 (leads.csv, founder alerts for non-fits and handoffs, every conversation mirrored live to Telegram), all verified with offline checks and live test conversations.
- Linked the whole project into Obsidian as live links (89+ files), with a "START HERE" map that rebuilds automatically each session start.
- Fixed a session-state bug where Render restarts wiped conversations mid-chat, by sealing conversation state into the browser and returning it with every request; verified on Render.
- Diagnosed and fixed a Telegram delivery failure caused by the group becoming a "supergroup" (new chat ID) when the founder was added; updated the ID in .env and .env.example; the Render change was left to Ioseb and is not yet confirmed.
- Changed chatbot behavior per founder/Ioseb requests: ask only for state (not city+state) for location, removed the "currently open and serving customers" fit question, recognized more buying-intent phrases, stopped repeated founder-handoff offers, removed scope claims outside approved answers.
- Installed the founders' final v2 approved-answers file, tested it with 16 real questions, and fixed a case where the bot invented an end date for introductory pricing.
- Copied `content/approved-answers.md` to the Desktop for Ioseb to send to the founders.

## Decisions

- CLAUDE.md split immediately rather than left long, even while the other terminal was actively editing it (Ioseb's choice).

- Every visitor conversation now goes to Telegram live, message by message, rather than only after 30 quiet minutes (Ioseb's choice).
- Keep Sonnet as the model everywhere (including Render), withdrawing an earlier proposal to use Haiku for cheaper testing (Ioseb's choice).

## Problems and lessons
- Telegram and founder-email alerts silently did nothing for a period because `.env` did not exist on the Mac; nothing surfaced this until Claude checked manually. A missing-config failure should be visible, not silent.
- Adding the founder to the Telegram group silently changed the group's chat ID (supergroup upgrade), breaking all alerts until diagnosed via the Telegram API directly.
- Common buying phrases ("I want to use...", "sign me up") were not recognized as purchase intent and had to be added in two passes, the first pass being too broad (falsely matching "What services do you offer?").
- The bot invented an unapproved fact (a nonexistent end date for introductory pricing) during testing; this was caught and fixed, then retested to confirm it stopped happening.
- The founder's early-session confusion ("gmial.com" typo, "LA" ambiguity between Louisiana and Los Angeles) showed that visitor input needs confirmation prompts, which the bot already does for state ambiguity but not yet for email typos.
- Two Claude Code terminals editing the same repo caused decisions to be committed to the old CLAUDE.md location until that terminal is restarted or given the new file to read.
