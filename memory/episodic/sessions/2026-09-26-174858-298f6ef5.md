## Goal
Ioseb asked for a full audit of the project's session-management and workflow setup (memory layers, handoff/compaction, session summaries, proposals, SDLC cycle), then wanted the gaps fixed and one approved improvement (alert failure warnings) built and shipped.

## What was done
- Audited the workflow against the original setup brief and against the intent/spec/plan/build/test/deploy/maintain cycle; found real gaps (no PR flow, no automated evals, lost/duplicate session summaries, 15 undecided proposals, stale CLAUDE.md notes, an untested compaction path).
- Built and merged 10 fixes on a branch, opened as pull request #1 (merged): commit-label hook, push guard blocking direct pushes to main, one-command eval runner (`tests.evals`) covering 17 scripted conversations, fixed session-summary file collisions and per-session failure records, made the PreCompact hook actually run (was silently failing every time before this session), added intent-change prompts to the phase-gate, wrote ADR 0020, moved stale dated notes from CLAUDE.md to `docs/build-log.md`.
- Ran a real compaction 3 times on a throwaway session to verify the counter and "open a new terminal" warning actually fire.
- Reviewed all 15 pending proposals with Ioseb: 3 approved (0013, 0014, 0015), 1 turned into a standing rule (0005), 2 deferred (0002, 0003), 6 rejected (0004, 0007, 0008, 0009, 0010, 0011).
- Built proposal 0013 (alert failure warnings) on branch `phase-5-alert-check`, opened as pull request #2, code-reviewed, fixed 2 review findings, merged. If Telegram breaks, founders get an email with the fix; if email breaks, they get a Telegram message; at most one warning per hour per channel; `/health` shows alert status without exposing the failure reason publicly.
- Verified live on Render: `/health` shows `"alerts": {"telegram": "ok", "email": "ok"}`, confirming the Telegram group ID fix from the earlier incident is in place.
- Started the emergency off-switch (`CHAT_ENABLED`), then rolled it back cleanly (branch removed, no code left) when Ioseb said skip.

## Decisions
- Audit approach: audit current setup first, before making changes. Chosen by Ioseb.
- All 10 workflow fixes approved. Chosen by Ioseb.
- Deploy step: full PR flow (branch, PR, code review, merge = approval). Chosen by Ioseb over the lighter no-PR option.
- Alert failure notification: warn on the other working channel (Telegram down → email; email down → Telegram). Chosen by Ioseb.
- Disposition of the 12 pending proposals as listed above. Chosen by Ioseb.
- Off switch and 30-day auto-delete: skipped for now, to revisit later. Chosen by Ioseb.

## Problems and lessons
- The PreCompact hook had been silently rejected by Claude Code on every past compaction, so its instructions were never applied; this was only caught by running a real compaction, not by unit tests. Future workflow changes to hooks need at least one real end-to-end run before being trusted.
- Throwaway test sessions (used to test compaction) got summarized like real sessions, creating duplicate/misleading proposals that had to be manually found and deleted.
- Explaining a not-yet-built feature (the off switch) with concrete Render step-by-step instructions confused Ioseb into thinking it might already be live and affecting the chatbot, causing frustration. Not-yet-built features should be flagged as not built before any usage steps are given, and re-confirmed if the user seems unsure.
- Scripted text edits should fail loudly if the target text isn't found rather than silently doing nothing; this is now a standing rule (from proposal 0005).
