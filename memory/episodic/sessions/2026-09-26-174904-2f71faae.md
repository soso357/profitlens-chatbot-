## Goal
Ioseb wants Claude Code to have a general-purpose project foundation (context engineering, memory layers, agent harness, spec-driven workflow, and CI), not just chatbot-specific setup, and asked Claude to design and build this incrementally with his approval at each step.

## What was done
- Interview conducted; answers recorded in ADR 0022 (session types, parallel-terminal workflow, handoff and compaction behavior).
- Design doc `docs/foundation-v2.md` written covering all 8 requested areas; choices C1-C7 recorded in ADR 0023.
- Step 1 (per-task handoff notes, `resume` flow, `docs/progress.md`, status bar changes at 60/70/85%, parallel-task skill, incident note template) built, reviewed, and merged (PR #3).
- Step 2 (`distribute.py`: session summaries auto-sorted into `progress.md`; plan/spec/rule changes become approval-gated proposals; stale memory flagging and cleanup) built, reviewed, and merged (PR #4).
- Step 3 (agent harness: allow/ask/deny lists in `settings.json`, `guard.py` hook blocking any read of `.env`) built, reviewed, and merged (PR #5).
- Step 4 (spec versioned to 1.0 with approval status and a text fingerprint so edits revert it to Draft; rules linked to their tests) built, reviewed, and merged (PR #6). Revealed 7 spec rules with no test yet, including rate limit, daily spend cap, and kill switch.
- Step 5 (GitHub Actions CI: ruff, mypy, pip-audit, secret scan) built, reviewed, and merged (PR #7).
- Fixed a pre-existing bug where session summaries always showed as "unreviewed" due to an unclosed frontmatter header.
- Removed all Zoho references from the spec, intent file, and glossary at Ioseb's request.
- Repository made public (Ioseb's choice) to unlock GitHub's free branch protection rule.

## Decisions
- Foundation-v2 scope and workflow answers (session types, parallel terminals via one handoff per task, sessions load nothing until "resume") ,  chosen by Ioseb.
- At 70% context: hand off to a fresh session; automatic compaction only as a safety net at 85% ,  chosen by Ioseb.
- C1-C7 design choices (progress.md, git worktrees for parallel terminals, soft stop at 70%, typed Obsidian context-graph links, approved dev tools ruff/pytest/pip-audit/GitHub Actions/secret scanner, multi-model design-only for now, 7-step build order) ,  all recommended options accepted by Ioseb.
- Remove Zoho from spec, intent, and glossary since email goes through Gmail ,  chosen by Ioseb.
- To enable free GitHub branch protection, make the repository public rather than pay for GitHub Pro ,  chosen by Ioseb, after being told this exposes founders' brief, internal notes, emails, and the chatbot's full instructions.

## Problems and lessons
- The summarizer script sometimes left the frontmatter header unclosed, causing every summary to appear "unreviewed" regardless of actual review status; fixed by having the script close the header itself instead of relying on the model.
- Code review after each step consistently caught real bugs that offline tests missed: worktree path bugs in step 1, a title-prefix bug that made distinct proposals look like duplicates in step 2, a permission-order bug where "ask" rules silently overrode "allow" rules in step 3, and a spec-approval gap in step 4 where rewriting the whole spec file could keep it marked "Approved" without new sign-off. Running the review before every pull request is what caught these.
- A one-off 434-second slowdown in the workflow test could not be reproduced and was not a real bug; isolated unreproducible slow runs should be treated as noise rather than investigated further.
